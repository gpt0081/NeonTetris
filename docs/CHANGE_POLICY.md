# Change Policy

## 기본 원칙

새 요구사항은 기존 기능 위에 쌓는다; 기존 기능을 없애는 것은 기본 동작이 아니다.

## 변경 절차

1. main에서 새 브랜치를 만든다.
2. 코드 변경 전에 FEATURE_CONTRACT의 영향을 확인한다.
3. 변경 후 npm test를 통과시킨다.
4. Playwright 브라우저 스모크 테스트를 통과시킨다.
5. CI가 생성한 현재 화면 스크린샷 artifact를 확인한다.
6. PR 설명에 기존 기능 영향 여부를 기록한다.
7. main 반영 후 배포한다.

## 회귀가 발견되면

- 새 기능을 억지로 유지하지 않는다.
- 마지막 정상 main 커밋을 기준으로 회귀 지점을 찾는다.
- 기존 기능 복원 후 새 기능을 다시 얹는다.

## 고정 계약 변경

사용자가 기존 동작을 의도적으로 바꾸라고 요청한 경우에만 FEATURE_CONTRACT를 함께 수정한다.
